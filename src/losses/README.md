# Функции потерь

Локальный пакет с API в духе timm, как у `src/decoders`. Цель обучения
выбирается из конфига, а не правкой кода, поэтому арм эксперимента — это одна
секция YAML. `bce_dice` — обёртка над `SegmentationLoss` (`legacy.py`): та же
цель, что была до реестра, с `dice_scope`/`dice_weight` и поддержкой
DCT-головы. Остальные пять целей — подклассы `LossArm` (`base.py`).

```python
from src.losses import create_loss, is_loss, list_losses

list_losses()      # ['aic_harmonic', 'aic_surrogate', 'balanced_bce_dice',
                   #  'bce_dice', 'focal_dice', 'focal_tversky']
list_losses('aic*')  # ['aic_harmonic', 'aic_surrogate']

loss_fn = create_loss('aic_surrogate', aux_weight=0.4, fpr_weight=1.0)
result = loss_fn(model_output, batch)  # LossResult(total, components, diagnostics)
```

## Конфигурация эксперимента

```yaml
loss:
  name: aic_surrogate
  kwargs:
    fpr_weight: 1.0
    area_threshold: 0.01
    area_mode: sigmoid
```

Секция необязательная: без неё берётся `bce_dice` — ровно та формула, что была
до реестра, поэтому старые конфиги считают то же самое. `dice_scope` и
`dice_weight` — top-level ключи `loss:`, но действуют только на `bce_dice`;
остальные цели получают параметры через `kwargs`.

`aux_weight`/`dct_aux_weight` в `loss.kwargs` не передаются: они же включают
aux- и DCT-головы в декодере и остаются в `model`, откуда их берёт
`build_loss`. Иначе конфиг мог бы попросить глубокую супервизию у модели,
собранной без неё. Неизвестный ключ в `kwargs` вызывает `TypeError`, а не
игнорируется молча.

Имя цели попадает в снапшот прогона (`loss_name`) и в `summary.json`.
Продолжить прогон (`resume: true`) с другой функцией потерь нельзя — это была
бы уже другая кривая обучения под тем же именем.

## Что где считается

Все цели реестра наследуют `LossArm` и реализуют только `mask_term`, возвращая
именованные слагаемые (`{"bce": ..., "dice": ...}` и так далее). Общее — BCE по
голове-гейту, то же слагаемое для aux-головы и (при `dct_aux_weight > 0`) для
DCT-головы на её родном разрешении:

```
components = mask_term(logits) | {"cls": cls_weight * BCE(cls_logits)}
           | {f"aux_{k}": aux_weight * v for k, v in mask_term(aux_logits).items()}
           | {f"dct_aux_{k}": dct_aux_weight * v for k, v in mask_term(dct_aux_logits).items()}
total = sum(components.values())
```

Диагностика (`dice_pos`, `dice_neg` в `LossResult.diagnostics`) всегда считает
обычный Dice основной головы по всем кадрам, независимо от того, что на самом
деле обучает `mask_term`, — иначе арм с другим слагаемым нечем было бы сравнить
с остальными в `LossMeter`/логах эпохи.

`MaskBatch` раскладывает батч по кадрам: `dice`, `tversky`, `bce`,
`predicted_area`, `is_positive` возвращают вектор длины B. Так и устроена
метрика — среднее по кадрам, а не по пикселям, и с разными правилами для
позитивов и негативов. Всё считается в float32: под bf16 площадь около 1%
кадра различима плохо. Паддинг letterbox исключается через `valid_mask`.

## Армы

| имя | слагаемое по маске | какую гипотезу проверяет |
| --- | --- | --- |
| `bce_dice` | `BCE + Dice`, по всем кадрам (`dice_scope`/`dice_weight`) | контроль |
| `balanced_bce_dice` | BCE с весом позитивных пикселей до `max_pos_weight` | правка на 0.5% кадра даёт 0.5% слагаемых BCE и теряется на фоне |
| `focal_dice` | focal-перевес BCE | то же, но перевес идёт по уверенности, а не по площади разметки |
| `focal_tversky` | `BCE + (1 - Tversky)^gamma` | Dice одинаково штрафует пропуск и ложное срабатывание, из-за чего на маленькой маске выгодно молчать |
| `aic_surrogate` | `BCE + Dice(позитивы) + мягкий FPR(негативы)` | Dice берёт с негатива почти полный штраф за любое пятно, а метрика не замечает ничего до 1% кадра |
| `aic_harmonic` | `BCE + (1 - AIC по батчу)` | свёртка тоже как в метрике: сама переносит градиент на ту компоненту, которая сейчас хуже |

`focal_dice` и `balanced_bce_dice` делят BCE на сумму весов, а не на число
пикселей. Иначе перевес заодно менял бы масштаб всего слагаемого относительно
Dice, и эксперимент мерил бы две вещи сразу.

## Мягкий FPR

Метрика считает негативный кадр ложной тревогой при площади предсказания от 1%.
Индикатор недифференцируем, `soft_false_positive` даёт три замены:

| режим | 0.2% | 0.5% | 1% | 5% | 50% |
| --- | ---: | ---: | ---: | ---: | ---: |
| `sigmoid` | 0.04 | 0.20 | 0.50 | 0.96 | 1.00 |
| `rational` | 0.17 | 0.33 | 0.50 | 0.83 | 0.98 |
| `hinge` | 0.27 | 0.45 | 1.00 | 11.5 | 141.4 |

`hinge` точнее всех повторяет форму метрики, но не ограничен сверху: на
случайной инициализации площадь предсказания около 50%, слагаемое уходит за 140
и подминает под себя весь градиент — с `grad_clip` это значит, что первые эпохи
модель учится только молчать. Поэтому по умолчанию берутся ограниченные режимы,
а `hinge` остаётся для отдельной проверки с маленьким `fpr_weight`.

У ограниченных режимов далеко над порогом градиент затухает, поэтому рядом
всегда остаётся пиксельная BCE: она удерживает негативы в начале обучения, пока
площадь ещё далека от порога. Разница с контролем в другом — из негативов
убран Dice.

## Добавление цели

1. Создать модуль, например `src/losses/lovasz.py`.
2. Унаследовать класс от `LossArm`, добавить `@register_loss('lovasz')`.
3. Импортировать модуль в `src/losses/__init__.py`.

Конструктор принимает `cls_weight`, `aux_weight`, `dct_aux_weight` и
собственные именованные параметры. Не добавляйте поглощающий `**kwargs`, чтобы
опечатки в конфигурации обнаруживались при сборке, а не через полчаса обучения.

Контракт: `mask_term(logits, targets, valid_mask)` возвращает словарь именованных
слагаемых по одной голове (например, `{"bce": ..., "dice": ...}`). Логиты
приходят уже увеличенными до размера изображения, `valid_mask` может быть
`None` (режим `stretch`).
